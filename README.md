# 书架星系 · 暗物质图书馆

> 下一代图书馆不只帮你找到书；它把每一部真实作品变成一颗可追问、可偏航、可带走的星，让你有意义地迷路。

**[进入在线 Demo](https://vincejan.github.io/Book-Galaxy/)** · **[查看 GitHub 仓库](https://github.com/VinceJan/Book-Galaxy)** · **[数据来源与许可](data-sources.md)** · **[数据归属说明](DATA_LICENSE.md)**

![书架星系首屏：由真实书籍构成的暗物质图书馆](docs/hero-preview.png)

「书架星系」是一件面向普通读者的屏幕端数字艺术作品。你从一本熟悉的书出发，进入一片没有围墙的三维星海：每颗星都是真实作品，近处有回声，远处有裂隙，偶尔还有一条只在此刻显形的暗线，把两本原以为无关的书牵到一起。你可以靠近、转身、偏航；走过的书，最后会留下只属于这次阅读的未刊星图。

同一片星海，也回答两个问题：

- 对赛题 02「图书馆的超进化」，它把图书馆从“找到书就结束”的入口，变成一处可以继续漫游的阅读空间：下一本书不必被检索出来，也可以在远处被遇见。
- 对赛题 03「制造一点意外」，它把意外变成一条仍有线索可循、却没有提前写好的路；馆员不替用户安排路线，只在被召唤时把一次相遇说得更远。

这片星海的三项底数是 **1,000 本真实书籍、5,380 条书海暗线、3,002 条引力书线**。数字只是星海的密度；真正重要的是每颗星背后的书页，以及下一次相遇。

快照的内容底数同样可核查：中文摘要覆盖率 100%，每本至少 120 个汉字，中位数 214 个汉字；571 本带有可解析的 Open Library 真实封面（57.1%），其余显示程序化书目牌。925 本具有可核查的具名作者记录；其余按来源标明佚名、多人合著或传统归属。每本书至少连接 6 条可漫游暗线，1,000 本全部覆盖 `near`、`bridge`、`far` 三档；引力书线为 1,000 / 1,000 本全部覆盖，每本至少一条。

## 同一体验，双赛题证据链

| 赛题 | 作品中的回答 | 现场可以验证的证据 |
| --- | --- | --- |
| 02 · 图书馆的超进化 | 图书馆可以从“检索终点”变成一台帮助普通人探索的阅读观测仪。 | 每颗星对应一部真实作品；中文题名、作者、年代、主题、摘要、来源和封面状态都能在观测台查看；星海支持拖拽、缩放、悬停、点选、回到出发星和航迹记录；三本书后可以留下可下载的星图。 |
| 03 · 制造一点意外 | 意外不必是没有依据的随机数，而可以是用户主动选择的一条“仍然说得通、但没有预告”的路；更高级的意外，是让两本书在一个此前没想到的世界知识或人类经验上相遇。 | 偏航罗盘把熟悉、过桥和远行放在同一条路上；独立的引力书线把远处的两部作品牵到一起，并明确标为阅读假说；抵达后先让书页自己发声，用户主动点击才召唤馆员波段；最终星图保存了相遇的物证。 |

回声、镜像、暗河、裂隙、余烬、潮汐不是学科标签，而是这趟旅程的六种天气：它们让关系有了方向，也给意外留下余地。每一次相遇都把事实、推断和想象分开，让大胆不必伪装成定论。

## 3 分钟路演

使用普通显示器和浏览器全屏即可。整段演示只需要一条主线：从熟悉的书出发，在意外处停一下，带走一张星图。

1. **0:00 — 先提出命题。** 进入页面，让评委先看到“让你有意义地迷路”。在「从一本熟悉的书出发」里输入《红楼梦》，点击「开始偏航」。
2. **0:20 — 让评委看到星海。** 拖拽旋转、滚轮缩放，先看三项底数：**1,000 本真实书籍、5,380 条书海暗线、3,002 条引力书线**。点击已显示列表中的《红楼梦》，让评委看见中文题名、作者、书页一瞥、主题、封面或书目牌，以及书页出处；这不是一张随机背景，每颗星背后都有一部真实作品。
3. **0:50 — 先走一段路。** 点击「从这里偏航」，进入「选择偏航方向」；任选一块方向牌，跟着镜头抵达下一颗书星。让评委看到，熟悉的书可以靠近，也可以把航向交给更远处。
4. **1:25 — 让一条引力书线显形。** 点击「返回出发星」回到《红楼梦》，在详情页点击「引力书线」，点击《沙丘》。大观园的家族盛衰与情欲无常，会在远处遇见厄拉科斯的香料、预言与帝国政治：不是把两部作品说成互相影响，而是让它们在一条意外的暗线上彼此照见。若评委想追问，再点击「请馆员说说这段缘分」；馆员只在此刻出现。
5. **2:10 — 把脚步留下。** 再完成一至两次「从这里偏航」，直到左下角的「本次航迹」至少有三本书；点击「留下这次迷路」，让经过的书和路线沉到纸面。
6. **2:35 — 带走星图。** 在显影画面点击「保存高清星图」。最后停在这张只属于本次阅读的未刊星图上，让评委看到：图书馆的出口不是结果，而是下一次出发。

现场时间更短时，保留“《红楼梦》→从这里偏航→返回出发星→引力书线《沙丘》→留下这次迷路→未刊星图”这一条主线即可。

## 核心体验

### 1. 每颗星都先是一部有内容的书

当前快照只收录拥有中文页面、中文题名、作者或明确“佚名”标识、至少三个主题和可核查中文内容的作品。每本书至少有 120 个汉字的中文摘要，同时保留：

- 中文题名优先显示；有外文题名时作为次级信息；
- 作者或“佚名”标识，以及来源可核查时的年代、语言、地域、作品类型和主题；
- 中文维基百科页面与固定修订链接；
- 可核查的作品来源与主题依据；
- 可靠匹配的真实封面，或一张克制的程序化书目牌。

没有摘要、来源或资格证明的记录不会因为“想要更多星星”而被放进正式星海。

### 2. 星海是连续的，不是几团硬边界

书籍不会被切成边界清楚的几团：相近的气质自然靠拢，不同的语境之间渐渐搭桥，罕见的声音则留在较远处。主题只是观测时的一束微光，不是把作品关进格子。

用户不会同时看到一张难以阅读的关系蜘蛛网。选中作品后，罗盘只显影眼前的近、桥、远三种航向。每次航行都会诚实留下书名与来处；只有沿引力书线抵达时，才保留可读的策展句。

远方也不是随机跳转：它只是把一条不那么熟悉、却仍然说得通的路放到你面前。于是“偏航”不是离开阅读，而是把问题带到另一种光线里。

### 3. 引力书线：把意外写成一条可追问的阅读假说

星海负责把“附近”显出来；引力书线则把目光引向更远处：它可能从人物的命运、共同主题、叙事方法，或一个跨越地域的生活经验出发，让原本不相邻的两部作品在同一束光里相认。当前版本有 3,002 条这样的书线，覆盖 1,000 / 1,000 本书、每本至少一条；它们不冒充作者影响、引用、改编或文学史因果。

每条书线都牵着两部真实作品，配有关系类型和一段可朗读的中文句子，并明确写着“阅读假说”。它由模型辅助的逐书策展式近读与联想生成，再经过自动门禁与抽样质量门禁；它不是答案，只是一位有品位的陌生人替你指出的方向。观测台最多展示三条，让相遇保持稀薄，也让每一条都值得停留。

### 4. AI 是隐身的馆员

默认首页没有聊天框。观测台先让书页自己发声；只有用户主动点击「请馆员说说这段缘分」（独自观测时为「听听这颗书星」），馆员波段才出现。你可以让它把眼前的相遇说得更远，也可以什么都不问，继续沿着星光走。

### 5. 一次迷路可以成为一件作品

三本书以上的航迹可以导出为 3200 × 1800 的高清纸面星图。它不是当前屏幕截图，而是一张重新排版的出版物：有航线、书名、日期和“迷路”朱印；若最后一跳来自引力书线，还会保留那句策展文字。

## 视觉编码

视觉方向刻意避开廉价的赛博朋克霓虹，使用黑色观测台、墨黑与米灰纸面、旧金线、翡翠灰、冷 slate 与克制的赭色。下表是“数据如何变成画面”的简表：

| 数据 / 交互 | 画面语言 |
| --- | --- |
| position | 由语义布局提供的三维坐标；旋转和缩放保持深度关系。 |
| localDensity / semanticDensity | 局部书星密度；决定星点聚散、尘埃集中度和部分光晕强度。 |
| magnitude | 书星的相对体量与可见度；不是简单把所有书画成同样大小。 |
| shape | 程序化着色器形态：orb、ring、diamond、petal、seed、cross、flare；同一片星域中有不同的星体性格。 |
| halo / temperature | 光晕、脉动和白、翡翠、冷灰、赭金之间的低饱和色阶；不是把颜色硬编码成学科标签。 |
| outlierScore | 较疏、较远、带一点偏心的孤星感；它是相对语义位置，不是“价值较低”的评分。 |
| basis / evidence | 用户主动偏航后出现的金色航线、信标和关系说明；证据与联想分层呈现。 |
| clusterLabels / 主题 | 稀薄的语义区域提示；相邻区域可以重叠，不宣称存在清楚的学科边界。 |
| 航迹 | 左下角的书目轨迹与最终纸面星图；让一次探索有回忆、有出口。 |

星点由一个共享 BufferGeometry 和 WebGL 着色器批量渲染，React 只管理交互状态；因此规模扩大时不会为每本书创建一个 DOM 节点。

## 数据质量硬门槛

正式 v2 数据由脚本生成并在合并前 fail closed。核心门槛如下：

1. **作品资格：** 候选来自 Wikidata 中文维基百科 sitelink；只接受共享策略文件列出的直接 P31 作品类型。硬拒绝类型优先，系列、默认集合和无法确认的实体隔离，不沿 P279* 子类路径放宽。
2. **中文内容：** title 必须含中文；每本摘要至少含 120 个汉字，不能是“暂无简介”等占位文本。摘要、题名和来源页保留固定修订回链。
3. **可核查元数据：** 作者字段（来源未署作者时明确为“佚名”）、作品类型、主题和来源必须存在；主题不少于三项，并由 themeProvenance 逐项记录来自 Wikidata claim、摘要规则、上下文元数据或受控兜底。
4. **封面诚实：** 只有同时具备可靠 Open Library work ID、Open Library cover_i 和 HTTPS 封面 URL 时才展示封面；没有可靠匹配就展示程序化书目牌，绝不伪造图片。
5. **关系诚实：** 每条正式可漫游关系都必须有多维书目语义证据，并至少有主题、时代、地域中的一项可重算元数据证据；不得自环、悬空、重复或把关系句当作文学史结论。每本书至少保留六条通过检查的关系，并逐书覆盖 `near`、`bridge`、`far` 三档。
6. **布局可验证性：** 已提交快照可用 `manifest.json` 中的 SHA-256 验证；仅在固定输入、依赖、模型权重与参数相同的情况下，语义布局才承诺可重复。在线数据、依赖或模型修订后不保证字节一致。检查脚本仍会验证关系覆盖、连通性、空间—语义近邻重合和密度排序，而不是只验证 JSON 能否解析。

每次发布的精确书数、语义关系数、覆盖率、模型和 seed 见 public/data/manifest.json；引力书线的有效数量与覆盖统计见 `check:curated` 输出。data/rich/eligibility-report.json 保存候选被接受、拒绝或隔离的可审计记录。

## 事实、推断与意外的边界

| 层级 | 可以说什么 | 不可以说什么 |
| --- | --- | --- |
| 书目事实 | 题名、作者、年代、语言、地域、作品类型、主题、中文摘要、来源页和固定修订。 | 把缺失字段猜成事实，或把 Open Library 的图片 URL说成版权授权。 |
| 星海位置 | 作品的共同气质、时代与地域让星点靠近或远去。 | 把星点的靠近解释为作者影响、引用、改编或文学史因果。 |
| 星海关系 | 书海暗线只回答位置与航向；抵达后诚实记录从哪本书来到哪本书。 | 把算法关系句包装成作品解读，或借“回声”“暗河”“镜像”等叙事词冒充学术结论。 |
| 引力书线 | 一条从逐书阅读与世界知识联想生出的暗线；每条都明确是阅读假说，界面最多展示三条。 | 把阅读假说说成作者影响、引用、改编、传播链或文学史因果；把它混写成星海的基础关系。 |
| 在线馆员 | 用户主动提问后生成的新解释或大胆联想。 | 把远程模型回答当作本地关系图谱的来源，或在没有来源时声称确定。 |

因此，项目可以大胆地制造意外，同时把不确定性显式标出来：评委看到的是一条有证据、有边界的相遇路径，不是将猜测冒充权威。

```text
数据源
  ├─ Wikidata Query Service
  │    └─ 中文维基百科 sitelink + 直接 P31 allowlist

  ├─ 中文维基百科 MediaWiki API（zh-cn、导语、固定 oldid）
  └─ Open Library Search / Covers（只保留真实封面 URL）
             │
             ▼
scripts/build-rich-catalog.mjs
  ├─ direct-P31 fail-closed 资格评估
  ├─ 中文题名、摘要、主题、来源和封面 enrichment
  └─ data/rich/books.json + eligibility-report.json
             │
             ▼
scripts/build-semantic-layout.py
  ├─ BAAI/bge-small-zh-v1.5 中文向量
  ├─ cosine kNN（语义邻居与关系候选）
  ├─ DensMAP 3D（连续密度布局）
  └─ data/rich/layout.json（坐标、星体参数、关系 evidence）
              │
              ├───────────────┐
              ▼               ▼
scripts/assemble-v2-catalog.mjs   src/data/curatedThreads/*.ts
  ├─ 重新校验 rich books + layout   ├─ reading-hypothesis 独立策展层
  ├─ public/data/catalog.json       ├─ 模型辅助逐书近读/世界知识联想
  ├─ public/data/manifest.json      └─ 不进入 BGE/DensMAP 关系和三档排序
  └─ scripts/build-attribution.mjs
              │               │
              └───────┬───────┘
                      ▼
浏览器
  ├─ React 19：体验状态、航迹、偏航罗盘、观测台、馆员波段、星图
  ├─ Three.js / WebGL2：星云、书星、尘埃、拾取、镜头飞行、关系线
```

应用载入 catalog-v2 后才把正式快照交给星海；缺失或不完整的 v2 数据不会被静默当成正式全量目录。关系运行时还会再次过滤缺少语义与元数据依据的边，避免旧快照或手工修改污染用户体验。

## 本地运行

需要 Node.js 20.19+ 或 22.12+。语义数据重建另外需要 Python 3.11+；依赖写在 requirements-data.txt 中。

```bash
npm ci

# 开发服务器，默认 http://localhost:5173
npm run dev

# 生产构建
npm run build

# 预览生产构建
npm run preview

# 单元测试
npm test

# TypeScript 检查
npm run typecheck

# 测试 + 数据检查 + 生产构建
npm run check
```

进入页面后，应用先渲染一个可用的入口状态，再载入 public/data/catalog.json；正式快照加载失败时不会显示伪造的全量数字。浏览器端不需要下载模型，模型只在离线数据重建阶段运行。

## 重建正式数据

正式流水线需要访问 Wikidata、中文维基百科和 Open Library；响应缓存写入被 .gitignore 排除的 data/raw/rich-catalog/，中断后可以从缓存继续。先安装 Python 依赖：

```bash
python -m pip install -r requirements-data.txt
```

一步重建：

```bash
npm run build:data
```

它依次执行以下三个阶段：

```bash
# 1. 获取并筛选中文富书目；默认目标 1,000，候选倍数由 package.json 固定
npm run build:data:rich

# 2. 在 CPU 上生成确定性的语义三维布局和可解释关系
npm run build:data:layout

# 3. 合并 catalog-v2，并生成字段级归属侧车
npm run build:data:assemble
```

如果来源在一次重建中不足以满足目标，脚本会停止并要求增加候选或降低目标；它不会把只有书名的记录塞入星海。--limit 可用于本地实验，正式演示应以仓库提交的 v2 快照为准：

```bash
node scripts/build-rich-catalog.mjs --limit 1000 --candidate-multiplier 8
python scripts/build-semantic-layout.py --input data/rich/books.json --output data/rich/layout.json
node scripts/assemble-v2-catalog.mjs
node scripts/build-attribution.mjs
```

布局脚本支持 --model、--neighbors、--candidate-neighbors、--seed、--batch-size 和 --umap-neighbors；改变它们会改变布局与关系，应在提交前重新执行全部检查。

### 检查数据

```bash
npm run check:data
```

`check:data` 只检查正式数据快照，会依次运行：

```bash
npm run check:data:eligibility  # 资格策略的拒绝/隔离 fixture
npm run check:data:rich         # 中文内容、主题、来源、资格证明
npm run check:data:layout       # 坐标、kNN、密度、关系 evidence 和连通性
npm run check:data:catalog      # 最终 catalog、manifest、关系和覆盖率
npm run check:data:attribution  # ATTRIBUTION.json 与 catalog 字节级一致
```

### 完整发布检查

```bash
npm run check
```

完整发布检查在上述数据门禁之上，再运行 Vitest、TypeScript、`check:curated`（引力书线的 QID、去重、全书覆盖、集中度和文案门禁）、`check:copy`（公开界面与策展文案的技术套话门禁）以及生产构建。CI 和提交前验收应以 `npm run check` 为准。

旧版 Gutenberg 构建器仍可用于历史对照或离线实验，但它不属于正式中文 v2 星海：

```bash
npm run build:data:legacy
npm run check:data:legacy
```

legacy 输出不能覆盖 public/data/catalog.json，也不应在路演中宣称为正式星海来源。

## 可选在线馆员

只有配置 VITE_AI_ENDPOINT 后，馆员波段才显示追问入口。应用发送当前问题、出发书、抵达书和最近五本航迹；只有引力书线会附带策展句与依据，普通偏航只附带航向信息。接口期待收到：

```json
{ "answer": "一段不超过 900 个字符的解释" }
```

前端把问题限制为 240 个字符并在 8 秒后超时；浏览器不会保存或暴露模型私钥。远程 AI 只负责用户主动追问时的开放式解释，不生成正式书目、坐标或关系图谱。

```dotenv
VITE_AI_ENDPOINT=https://your-domain.example/api/curator
```

.env 不应提交到仓库；部署时把端点作为环境配置注入，并自行处理服务端鉴权、速率限制和内容安全。

## 静态部署

项目没有必需的后端，GitHub Pages、Cloudflare Pages、Netlify 或任意静态文件托管都可以运行已经构建的 dist/：

```bash
npm ci
npm run check
```

在 GitHub Pages 中使用 Actions 执行 npm ci、npm run build，再发布 dist/ artifact。Vite 使用相对 base，适合仓库项目子路径；如果改为固定绝对路径，再按托管平台调整 vite.config.ts。

## 未来图书馆适配器

当前 Demo 使用提交到仓库的静态快照，没有连接任何真实馆藏数据库。src/data/libraryAdapter.ts 提供纯函数 normalizeLibraryRecord()，可以在无网络副作用的情况下把常见中英文 CSV/JSON 馆藏记录规范化为应用 Book，并保留 ISBN、索书号、馆藏号和记录号等集成字段。

真正接入图书馆时，可以把 OPAC、馆藏 API 或定期导出接到 adapter，再使用同样的内容门槛和关系策略生成快照；星海渲染和体验层不需要重写。生产适配仍需由图书馆决定：

- 作品本体、版本、借阅记录和馆藏副本如何分层，避免同一本书因译本或副本变成无意义的重复星点；
- 哪些字段可以公开，哪些只在馆内使用；
- 真实馆藏来源的许可、版权和个人数据边界；
- 语义关系是否需要馆员审核、按学科定制或允许读者反馈。

未来可以在 loadGalaxy.ts 之前加入定期快照 adapter，把不同馆藏系统统一为稳定 ID、中文书目内容、来源回链与可解释关系；“可接入真实图书馆”是清晰的接口方向，不是当前 Demo 已经连接了真实数据库的声明。
